# 陶晶驰串口屏协作笔记

本文用于后续开发高精度数控恒流源的串口屏界面和 STM32 联调代码。资料来源为本目录下的 `官方网页.md`、`开发手册.pdf`、`例程.zip`，以及陶晶驰官方 wiki/官网页面入口。

## 1. 基本模型

陶晶驰串口屏的开发分两部分：

1. 在 PC 端的 USART HMI 工具里制作 HMI 工程，放置页面和控件，编写屏内事件脚本，然后编译生成 `*.tft` 下载到屏。
2. MCU 通过 UART 给屏幕发送 ASCII 指令，并解析屏幕返回的串口数据。

屏幕端不是普通液晶裸屏，而是带脚本解释器的 HMI 设备。绝大多数 UI 改动都可以通过类似 `控件.属性=值` 的命令完成，例如：

```c
tjc_send_string("main.t_set.txt=\"1.234\"");
tjc_send_string("main.n_current.val=1234");
tjc_send_string("page setting");
```

所有串口指令必须以 3 个字节 `0xff 0xff 0xff` 结尾。用 C 字符串发送时常写成：

```c
printf("n0.val=666\xff\xff\xff");
```

建议项目中封装一个 `tjc_send_cmd()`，统一追加结束符，避免漏发。

## 2. 串口与电气连接

常规连接：

- 屏幕 TX 接 STM32 RX。
- 屏幕 RX 接 STM32 TX。
- GND 共地。
- 屏幕按型号供电，常见为 5 V，实际以产品型号页和丝印为准。

默认联调建议：

- UART: `115200, 8N1`。
- 不开硬件流控。
- STM32 先用中断或 DMA 接收，进入环形缓冲区，再由主循环解析完整帧。

波特率相关：

- `baud=115200`：修改当前运行波特率，掉电不一定保存。
- `bauds=115200`：保存波特率配置，写入后通常需要复位/重新连接确认。
- HMI 工程 `program.s` 中常设置：

```text
bauds=115200
bkcmd=0
page 0
```

## 3. 指令格式

### 3.1 设置控件属性

文本控件：

```text
t0.txt="hello"
main.t_current.txt="12.345mA"
```

数值控件：

```text
n0.val=123
main.n_dac.val=32768
```

颜色、显隐、使能等属性也可直接设置，具体属性取决于控件类型。

### 3.2 页面跳转

```text
page 0
page main
```

建议正式项目使用页面名，减少页面 ID 改动带来的问题。

### 3.3 刷新与可见性

```text
ref t0          // 刷新单个控件
ref 0           // 刷新当前页
vis b0,0        // 隐藏 b0
vis b0,1        // 显示 b0
tsw b0,0        // 禁止触摸 b0
tsw b0,1        // 允许触摸 b0
tsw 255,0       // 禁止当前页所有控件触摸
tsw 255,1       // 恢复当前页所有控件触摸
```

实际工程中，进行危险操作或保存参数时可短暂 `tsw 255,0`，处理完成后恢复。

### 3.4 模拟点击

```text
click b0,1      // 触发按下事件
click b0,0      // 触发释放事件
```

可用于 MCU 主动驱动屏幕执行某个按钮事件，但正式项目更推荐把共用逻辑写成页面/控件事件脚本或 MCU 端函数，避免“假点击”导致状态难追。

### 3.5 获取控件值

```text
get n0.val
get t0.txt
```

屏幕会返回数值帧或字符串帧。MCU 必须按返回帧格式解析，不要把它当普通 ASCII 行。

### 3.6 屏幕主动发原始数据

屏内事件脚本常用：

```text
printh 55 01 04 01 ff ff ff
prints h0.val,1
```

- `printh` 发送十六进制字节。
- `prints` 发送变量原始内容，可按指定长度输出。

官方例程使用了自定义 7 字节帧：

```text
55 cmd data0 data1 ff ff ff
```

例如：

```text
printh 55 01 04 01 ff ff ff
```

表示命令 `0x01`，对象/通道 `0x04`，状态 `0x01`。

## 4. 屏幕返回帧

所有屏幕返回数据通常也以 `ff ff ff` 结束。常见帧包括：

- `0x65 page_id component_id event ff ff ff`：触摸事件返回。`event=0x01` 多表示按下，`event=0x00` 多表示释放。
- `0x66 page_id ff ff ff`：当前页面 ID 返回，常由 `sendme` 触发。
- `0x70 ascii... ff ff ff`：字符串数据返回，常由 `get t0.txt` 触发。
- `0x71 value[4] ff ff ff`：数值数据返回，常由 `get n0.val` 触发，数值通常为小端 32 位。
- `0x00 ff ff ff`、`0x01 ff ff ff` 等：指令执行状态返回，受 `bkcmd` 影响。
- `0x86 ff ff ff`：设备进入睡眠。
- `0x87 ff ff ff`：设备自动唤醒。
- `0x88 ff ff ff`：设备上电初始化完成。

`bkcmd` 控制指令执行结果是否返回：

- `bkcmd=0`：不返回普通指令执行结果，减少串口负担。
- `bkcmd=1/2/3`：按不同级别返回成功/失败信息，调试时可打开。

建议开发期使用 `bkcmd=3` 检查指令错误，正式运行改为 `bkcmd=0` 或低返回级别。

## 5. STM32 端建议架构

### 5.1 发送封装

建议最少实现：

```c
void tjc_send_cmd(const char *cmd);
void tjc_set_txt(const char *obj, const char *txt);
void tjc_set_val(const char *obj, int32_t val);
void tjc_page(const char *page_name);
```

实现要点：

- 所有函数最终都调用同一个 UART 发送函数。
- 自动追加 `0xff 0xff 0xff`。
- 文本值需要自动加双引号，例如 `t0.txt="abc"`。
- 避免在中断里拼接长字符串。

### 5.2 接收解析

推荐流程：

1. UART 中断或 DMA 收字节，写入环形缓冲。
2. 主循环或任务中查找完整帧，以 `ff ff ff` 作为帧尾。
3. 按首字节分发：
   - `0x65`：官方触摸事件。
   - `0x66`：页面 ID。
   - `0x70`：字符串返回。
   - `0x71`：数值返回。
   - `0x55` 或项目自定义帧头：屏内脚本主动发给 MCU 的业务命令。
4. 解析成功后从环形缓冲删除整帧；帧头不匹配时删除 1 字节重新同步。

官方 HAL 例程的 `deleteRingBuffer()` 代码中 `return` 位于 `for` 循环内部，按实际效果只删除 1 字节。移植时应修正为循环完成后再返回。

### 5.3 自定义协议建议

对恒流源项目，建议不用屏幕默认触摸事件直接承载业务，而是在屏内按钮/滑块事件里发自定义帧：

```text
55 cmd len payload... checksum ff ff ff
```

最简版可先使用：

```text
55 cmd data0 data1 ff ff ff
```

后续如果命令变多，再升级为带长度和校验的帧。命令建议预留：

- `0x01`：设置输出电流，单位可用 uA 或 0.001 mA。
- `0x02`：输出使能/关闭。
- `0x03`：切换量程或模式。
- `0x04`：请求 MCU 回传当前测量值。
- `0x05`：校准参数保存/读取。
- `0x06`：报警确认。

屏幕只负责输入意图，真正的限幅、斜坡、保护、校准换算必须在 MCU 端完成。

## 6. 恒流源界面初步拆分

建议页面：

- `main`：设定电流、实际电流、输出电压/功率、输出开关、状态/报警。
- `set`：数字键盘或步进设置，支持 mA/uA 单位。
- `cal`：校准入口，显示 DAC 码、ADC 原始值、拟合参数。
- `protect`：过压、过流、过温、合规电压余量等保护状态。
- `about` 或 `debug`：固件版本、屏幕版本、串口状态、原始测量值。

建议控件命名：

- 文本显示用 `t_` 前缀，如 `t_i_set`、`t_i_meas`、`t_status`。
- 数值变量用 `n_` 前缀，如 `n_i_set_ua`、`n_output_en`。
- 按钮用 `b_` 前缀，如 `b_out`、`b_set`、`b_cal_save`。
- 滑块用 `h_` 或 `j_` 前缀，具体跟工具默认控件类型保持一致。

MCU 定期刷新屏幕的内容：

- 设定电流。
- 实测电流。
- 输出电压或 MOS 管余量。
- DAC 码/ADC 码。
- 输出状态。
- 保护/报警状态。

屏幕发给 MCU 的内容：

- 用户确认后的设定值。
- 输出开关命令。
- 校准点确认。
- 页面切换后的数据请求。

## 7. 调试清单

1. 用 USB-TTL 单独连屏，确认 `baud` 和供电。
2. 串口助手发送 `page 0 ff ff ff`、`t0.txt="OK" ff ff ff` 验证屏幕接收。
3. 屏幕按钮事件写 `printh 55 01 01 01 ff ff ff`，串口助手确认返回。
4. STM32 接屏后先只打印/记录收到的十六进制帧。
5. 再打开业务解析，确认帧尾同步和异常帧恢复。
6. 最后才接入 DAC 输出控制，且必须在 MCU 端做电流限幅和输出使能保护。

## 8. 后续协作约定

后续我会按这个思路协助：

- 设计 HMI 页面时，先定页面名、控件名、事件帧。
- 写 STM32 代码时，先实现稳定的 `tjc_send` 和 `tjc_parse` 模块。
- 联调时，用串口助手先验证每条屏幕脚本，再接 MCU 业务逻辑。
- 所有危险输出命令都先进入 MCU 的安全状态机，屏幕命令不直接改 DAC。
